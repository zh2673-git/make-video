# MakeVideo 项目方案

> 生成时间：2026-09-24 | 方法论：project-development-prompt.md（时空运行时版）| 模式：生产

## 项目目标

MakeVideo 是一个**讲稿驱动的微视频生成工具**：一份符合分镜 DSL 的讲稿.md + 任选风格主题 → 一键 1080P MP4，零人工剪辑。三个设计目标：

1. **管线自动化**：配音、帧对齐、渲染、拼接全链路由确定性管线完成，人只负责写讲稿。
2. **风格资产化**：视觉风格沉淀为主题 token 体系，换主题即换风格、内容零改动。
3. **分镜语言**：内置 12 种分镜版式（title/bullets/flow/table/panorama/ending/quote/compare/timeline/chart/code/image），覆盖常见讲解形态。

## 本质定义（通过时空契约校验）

**本质**：一个把"人的讲稿时间"调度为"机器的逐帧渲染时间"的成片运行时；风格空间（主题）与内容空间（分镜）双向解耦，以"讲稿进、成片出"为唯一对外承诺。

**时空契约校验**：

| 契约维度 | 内容 |
|---|---|
| 空间归属 | 主题空间（themes/，全局共享只读）与工程空间（projects/，每视频独立）分离；中间产物（scenes.gen.json、mp3、分段 mp4）全部落盘可复用；运行结束无内存驻留 |
| 时间流形态 | **顺序管道**：解析讲稿 → 逐分镜 TTS → 帧数对齐 → 写分镜 JSON → Remotion 渲染（整片/分段增量）→ 无损拼接。单向推进、失败即停、可一键重跑 |
| 规则拦截 | 讲稿 DSL 与 theme.json 双 schema 运行时校验（Python 侧拦截）；分镜 type ↔ 组件映射表编译期固定（TS 侧 exhaustive match）；TTS 音频数 = 分镜数断言（stop 钩子）；缺 token 兜底默认值 + 告警 |

## 架构总览（第0级时空映射）

```
讲稿.md ──┐                                          ┌── 整片 MP4
          ├─[domain 解析/对齐]─[application 编排]─[infrastructure 渲染]┤
theme.json┘        ↑ schema 校验        ↑ 生命周期钩子          └── 分段缓存
styles/DESIGN.md ──→ themes/token（skill 流程转换，人审试帧）
```

| 时空层级 | 本项目对应 | 物理目录 | 核心职责（时空视角） |
|---|---|---|---|
| 数据规范（规则） | DSL/主题/错误契约 | makevideo/core/ | 定义分镜与主题的内存布局与合法性规则 |
| 数据存储（空间） | TTS/渲染/文件 IO | makevideo/infrastructure/ | 音频空间生产、帧空间渲染、产物落盘 |
| 流转-规则（业务时空） | 解析/字幕/对齐 | makevideo/domain/ | 讲稿文本在时间轴上切分、对齐为帧窗 |
| 流转-编排（调度时空） | 出片用例 | makevideo/application/ | 全量/增量/试帧三种时间线组装 |
| 运行时/内核（时空管家） | CLI 生命周期 | makevideo/runtime/ | init=解析校验 / start=TTS+对齐 / stop=数量断言 / destroy=落盘 |
| 数据接口（时空入口） | CLI 命令 | makevideo/runtime/cli.py | 将外部命令转化为出片用例调用 |
| 画面组件（消费侧） | Remotion 组件库 | makevideo/engine/ | 只读 theme token 渲染，零硬编码风格 |
| 风格资产 | 设计文档+token | styles/ + makevideo/themes/ | DESIGN.md 双源头 → theme.json 单契约面 |

**依赖铁律**：themes/engine 只被消费不被反向依赖；domain 不直接调 Remotion（经 infrastructure 接口注入）；CLI 是唯一调度入口。

## 模块递归四层设计（生命周期钩子见 docs/04~07）

| 模块 | 本质（锚定父本质） | 四层要点 | 生命周期落点 |
|---|---|---|---|
| 讲稿解析引擎（domain） | 把讲稿空间切分为分镜时间流的切分器 | 规范=DSL v2 契约；存储=讲稿.md 唯一源头；流转=块切分/字段提取/校验；接口=parse(md)→[Scene] | init=解析+结构断言 |
| 字幕与帧对齐引擎（domain） | 以配音时长驱动帧窗分配的对齐器 | 规范=帧=时长×30+尾帧；流转=切句/比例分配；接口=captions(narr,frames) | start=逐分镜对齐 |
| 主题系统（themes/styles） | 设计哲学到渲染 token 的翻译器 | 规范=theme.json schema；存储=token 库只读；流转=DESIGN.md→token 转换规则；接口=load(name)→Theme | init=token 校验 |
| 渲染引擎（engine） | 消费 token 与分镜 JSON 的逐帧画面工厂 | 规范=组件映射表；存储=scenes.gen.json+theme.gen.json；流转=Sequence 编排；接口=Remotion Composition | start=渲染，stop=退出码断言 |
| 出片编排（application） | 三种时间线（全量/增量/试帧）的组装器 | 规范=用例前置校验；流转=TTS→对齐→写 JSON→渲染→拼接 | stop=音频数断言，destroy=成片落盘 |
| CLI 运行时（runtime） | 命令到用例的调度管家 | 规范=命令表；流转=argparse 分发；接口=makevideo build/preview/validate | 显式 init/start/stop/destroy 映射 |

## 验证方式（P/Q/I）

| 维度 | 检查项 |
|---|---|
| P 前置 | Node+Remotion 可用；Chrome 路径存在；theme.json 校验通过；讲稿 DSL 校验通过 |
| Q 后置 | 示例工程端到端出片成功；各分镜类型渲染正确；换主题同讲稿出片风格生效、时长不变 |
| I 不变量 | 基础六型讲稿向后兼容；分段增量与整片逐帧一致；重跑幂等；无临时文件泄漏；移植主题与原 DESIGN.md 色板/字体抽查一致 |

详细测试执行见 docs/test-report-v1.md。

## 项目愿景

- **短期**：工具与主题系统落地，示例工程完整出片验证（本阶段交付）。
- **中期**：沉淀为 skill（结合 essence-workshop 工作流），"讲稿+主题"两参数出片；DESIGN.md→theme.json 的 AI 转换流程标准化。
- **长期**：批量视频生产线（系列课程换讲稿即换片），风格资产持续积累，形成"主题市场"。

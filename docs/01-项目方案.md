> 运行模式：生产 | 目标语言：TypeScript（Node 22+）| 依据：program.md（已确认）
> 方法论：project-development-prompt.md（时空运行时版）
>
> **文档树按"电影部门制"组织**（角色视角是主干，过程视角是投影）：
> 01 总纲 → 02 职能分工总论 → 03 编剧部 → 04 导演部 → 05 美术摄影部 →
> 06 采购部 → 07 声音部 → 08 剪辑部 → 09 工程部 →
> 10 视觉与剪辑规范（公共法律）→ 11 风格库与类型配方（公共注册库）→ 12 架构总览（工程地图）

## 项目目标

做一个"自动生成视频" Agent skill：输入一句主题（或直接提供讲稿/素材），自动完成
编剧 → 分镜 → 素材采购（画/用/找/生成四源智能决策）→ 旁白（TTS 或用户录音）
→ 时间线装配 → 渲染，输出完整成片 mp4，同时落盘可复用的项目文件
（`project.json` + 场景源码），支持改稿局部重渲染、单镜重试、断点续跑。

核心追求（用户原话）：**"如何用代码画出的图形成惊艳的视频，包括素材本身与动效。"**

## 本质定义（必须通过时空契约校验）

**本质定义**：make-video 是一个**视频编译器**——把自然语言创意（主题/讲稿）
编译为程序化绘制的动态视频：以代码（HTML/CSS/GSAP，经 HyperFrames 渲染）为第一画布，
用户素材与云端生成为兼容输入，旁白实测时长为时间基准，
显式状态机保证可断点、可重试、可人工精修；**规范笼子 + 风格包 + 类型配方**
三层保障把"惊艳"从运气变成配置；**电影部门制**（本文档树的主干）保证每个环节
都有专业容器承载理论与实践的打磨。

### 时空契约校验（方法论硬性门槛，三条自答）

1. **空间契约**：核心数据 = `project.json`（分镜表 + 镜头状态 + 决策记录）
   + 项目目录内资产。由单个项目目录**独占**；风格库/配方库/模板库/共享素材库
   被多项目**只读引用**（无可变共享，从结构上排除写冲突）。
   `init`（`make-video init`）开辟项目空间；`destroy`（`make-video clean`）
   按依赖逆序回收中间产物，保留成片与项目文件。跨边界共享均为只读，无竞争条件。
2. **时间契约**：主执行流为**状态机跳转**。镜头状态机
   `pending → sourcing → sourced → voicing → voiced → ready / failed`；
   阶段（script → storyboard → sourcing → voice → compose → render → done）
   由状态迁移驱动；云端任务等待为内嵌轮询 Loop；改稿/换素材/改风格是外部事件，
   触发局部重跑（时间流的分支/回跳）。
3. **规则契约**：三层拦截。编译期（TS 类型系统）→ 生成期（V-STYLE-* 组合一致性）
   → 运行期（V-* 不变量全家桶强制阻断）。场景代码不得直接读写 `project.json`；
   渲染器不得写素材目录——由依赖方向铁律预防。

## 双视角总纲（本篇档树的结构原则）

**做视频的本质是像拍电影那样思考。** 因此本方案有两个视角，且角色视角是主干：

| 视角 | 回答什么 | 在文档树中的位置 |
|---|---|---|
| **角色视角（主干）** | 谁对什么质量负责、依据什么专业理论打磨 | 02-09：每个电影部门一篇文档（职责/理论/工件/模块四层/校验域/反例/检查单） |
| **过程视角（投影）** | 数据往哪流、工程怎么落地 | 12：分层/数据流/选型/ADR/CLI/测试——它是部门协作在工程上的投影 |

三个结构原则：

1. **部门即模块的归口**：11 个电影角色归入 7 个部门 + 2 个公共注册库 + 1 张工程地图；
   每个部门文档内含其模块的递归四层设计（数据规范/存储/流转/接口）与生命周期钩子——
   方法论的"四层模型"不废除，成为部门内部规格。
2. **工件即交接契约**（ADR-9）：电影工业的第一危险是**翻译损耗**（剧本→分镜→镜单
   意图漂移），LLM 流水线每次模型调用都是一次翻译。对策：每个部门交接处强制留下
   **角色工件**（A1-A11），工件是契约、是质检对象、是人工精修的抓手。
3. **公共法律单一权威**：V-* 不变量只在 10 登记，各部门文档只引用不重复定义；
   风格包/配方只在 11 登记。防止规则散落打架。

### 工件链（一部视频的"生产流程"）

```
A1 项目章程（制片：program.md 实例化）
   └─▶ A2 讲稿·带功能标注（编剧部）
          └─▶ A3 导演批注（导演部：每段视觉意图/情绪目标/对位模式）
                 ├─▶ A4 确认表（导演部→用户：素材决策+风格决策+批注摘要，一次确认）
                 └─▶ A5 shot list（导演部：shots IR，分镜师产物）
                        ├─▶ A6 token set + 摄影计划（美术摄影部）
                        ├─▶ A7 表演设计（美术摄影部）
                        ├─▶ A11 资产清单（采购部：materials 索引 + AssetRef）
                        └─▶ A12 旁白与混音计划（声音部：VoiceRef + MixPlan）
                               └─▶ A8 时间线 + 剪切点审计（剪辑部）
                                      └─▶ A10 连续性报告（剪辑部·场记）
                                             └─▶ 成片 mp4（工程部）

风格侧平行工件链（导演部·风格决策与沉淀，详见 02/11）：
A13 风格解剖卡（anatomy 按部门键的指令集，用户可读）
   └─▶ A14 风格沉淀档案（absorb 的 provenance + 对拍结论 + 登记指令快照）
```

工件落点：A1-A5、A8、A10-A12 落 `project.json`（IR）；A6/A7 落场景源码与风格包引用；
调度日志与渲染报告落 `logs/`。**人机协作触点** = A3/A4（创意判断）、A10（质检）、
A8/A12（节奏/听觉微调）——人不需要读全量 IR 就能介入。

## 验证方式（P/Q/I + 部门验收门）

| 维度 | 检查项 | 时空说明 |
|---|---|---|
| P 前置 | `doctor` 全绿：Node 22/ffmpeg/Chrome/锁版本依赖 | 空间就绪 |
| Q 后置 | 端到端成片合法；时长档位（0-5/5-10/10min+）规格合规；段数=镜数；音画同步 <100ms | 时间流走通：七阶段全链路 |
| Q 后置 | 断点续跑：kill 后重跑零重复；混合流（用户录音+照片）同权无差 | 状态机可恢复 + 四源采购 |
| Q 后置 | **部门验收门**：五个重角色交付前检查单（02）全过；标杆对拍达标 | 每部门质量可检验 |
| Q 后置 | **新风格上架流程**：absorb → 解剖确认 → 小样对拍 → 注册 全链路跑通（V-STYLE-005/006） | 风格沉淀可用 |
| I 不变量 | 重复运行不损坏项目数据；单镜 retry 不影响他镜；schema/CLI 向后兼容 | 隔离性与原子写 |

时空闭环检查：所有 `init` 有对应 `destroy`；主循环可被 `stop` 优雅退出；
无跨层直接访问（场景代码不碰 IR 文件）。

## 项目愿景

- **近期**：单视频端到端跑通；分镜前一次确认（A4）；人工精修闭环
  （改 A3 批注/改 IR → 局部重渲）。
- **中期**：断点续跑 + 单镜重试成熟；混合素材工作流全量；`recipe-save` 沉淀新配方；
  部门验收门接入 `status`。
- **远期**：跨项目资产复用库；社区风格包/配方/模板生态（按部门分发）；
  从"自动生成"走向"可编程的视频工程"。

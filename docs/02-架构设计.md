# MakeVideo 架构设计

> 技术选型由时空需求推导（选型论证如何满足空间/时间/规则契约）。

## 架构图

| 层（自上而下调用） | 组件 | 说明 |
|---|---|---|
| 数据接口 | `makevideo runtime/cli.py` | build / preview / validate / list-themes 四命令 |
| 流转-编排 | `makevideo application/pipeline.py` | 三用例：full（全量）/ incremental（--only 增量）/ preview（主题试帧） |
| 流转-规则 | `makevideo domain/`（parser / captions / timeline） | 讲稿→分镜→帧窗，纯函数无 IO |
| 数据存储 | `makevideo infrastructure/`（tts / renderer / themeio） | edge-tts、Remotion 子进程、theme.json 读取 |
| 数据规范 | `makevideo core/`（schema / errors） | Scene/Project/Theme dataclass + 校验 + 错误码 |
| 消费侧 | `makevideo engine/src/`（React/TS） | 12 分镜组件 + 主题 CSS 注入层 |
| 风格资产 | `styles/` + `makevideo/themes/` | DESIGN.md（人审）→ theme.json（机器） |

```
工程空间 projects/{name}/          主题空间 themes/{name}/
  讲稿.md ┐                          theme.json ─┐
  project.json ├→ domain → scenes.gen.json ────→ engine 渲染 → out/*.mp4
  meta     ┘     ↑ TTS: public/audio/*.mp3 ────┘             ↑分段缓存 out/segments/
styles/{name}/DESIGN.md ──(skill转换+人审)──→ themes/{name}/theme.json
```

## 技术选型论证（时空需求 → 选型）

| 需求（时空契约推论） | 选型 | 论证 |
|---|---|---|
| 数据驱动：JSON 进 → 画面出 | Remotion | 唯一"组件直接吃 JSON"的成熟引擎；Manim/Motion Canvas 需二次翻译 |
| 主题零翻译落地 | Remotion + CSS token | canvas-design/DESIGN.md 的美学语言即 CSS 语言；色板/字体层级/阴影直接映射 |
| 中文排版 | Remotion DOM 排版 | 自动换行、字距、富文本远强于 Manim(LaTeX)/PIL |
| 时间确定性：配音时长驱动帧数 | edge-tts 词级时间戳 | 末词终点=音频时长，帧数=ceil(时长×30)+尾帧，音画永不漂移 |
| 空间轻量：免系统 ffmpeg | Remotion 自带 ffmpeg | 分段 `-c copy` 无损拼接，零额外依赖 |
| 迭代效率：改分镜不重渲全片 | Remotion --frames 分段渲染 | 已验证的增量模式，几十秒换段 |
| 编排确定性：失败即停 | Python 3.11 顺序管道 | 断言式 stop 钩子，无循环依赖 |
| 风格源头供给 | awesome-design-md + canvas-design | 移植型（现成 73 份）+ 原创型（设计哲学自写）双路 |

**否决记录**：Motion Canvas（无数据驱动管道、增量渲染无原生支持）；Manim（中文排版弱、LaTeX 依赖重、主题系统需二次翻译）；纯 ffmpeg+PIL（排版/动效全手写，主题成本最高）。

## design 风格系统集成

| 环节 | 机制 |
|---|---|
| 源头 A：移植型 | awesome-design-md（Google Stitch DESIGN.md 标准，73 份，MIT）选底稿 |
| 源头 B：原创型 | canvas-design 方法论自写设计哲学（政务等需避开品牌联想场景） |
| 视频扩展 | 每份 DESIGN.md 追加第 10 节「Motion & Video Rules」：动效曲线/转场节奏/字幕样式 |
| 转换规则 | 9 章节 Web 语义→视频画布：色板/字体层级/布局直接映射；**过滤** hover 态与响应式断点；阴影→层次参数 |
| 契约面 | theme.json 唯一：palette / semantic / typography / motion / layout / brand 六段 |
| 人审定稿 | skill 流程执行转换 → `makevideo preview` 6 宫格试帧 → 人审 → 入库 themes/ |

## 执行流类型

**顺序管道**（主），两处受控分支：
1. `--only` 增量：逐分镜判断缓存命中 → 命中复用/缺失重渲 → 仍为单向顺序，无并发。
2. `preview` 试帧：固定样例分镜跳过 TTS（定长帧），单一管道变体。

无事件循环、无状态机——视频出片是批处理任务，管道形态与其本质一致；时间复杂度集中于 Remotion 渲染，Python 编排开销可忽略。

# 编剧部（M2 scriptwriter）

> 角色：编剧 | 上游：制片（A1 章程、recipe/时长档位）| 下游：导演部（消费 A2）
> 模块：M2 | 校验域：V-SCP-*（10）| 反例卷：编剧卷

## 部门职责

把"一句主题"展开为**可拍摄的讲稿**：有结构（节拍覆盖）、有功能（每段三问居其一）、
有节奏控制（字数受时长档位约束）、有受众意识（术语密度匹配）。
编剧部是整部视频的**地基**——讲稿的功能结构直接决定下游分镜的语义单元。

## 输入输出工件

- **输入**：主题（或用户提供的讲稿文件）+ recipe（beats + durationTiers 字数目标）
  + 分类轴结论（受众专业度）。
- **输出工件 A2**：`Script { fullText, segments[{id, text, function, beat}] }`
  ——落 `project.json.script`；LLM 原始响应落 `cache/script.json`（审计重放）。

## 模块四层设计（M2）

- **数据规范**：`Script`/`ScriptSegment` zod schema（core）；`function ∈
  {advance, inform, emotion}`；段粒度 = 后续分镜的旁白单元；
  beat 字段对齐 recipe 节拍 id。
- **数据存储**：讲稿落 IR；原始响应落项目 `cache/`；不写任何共享目录。
- **数据流转**：
  ```
  topic(或用户讲稿) → LLM 结构化生成（系统提示含 recipe beats + 功能三问 + 字数目标）
    → zod 校验 → V-SCP-001~007 规则扫描 →（不过：带错误反馈重试 ≤3）
    → 分段 + 功能标注 + beat 对齐 → 写 IR → persist
  ```
- **数据接口**：`writeScript(p, topic?): Script`。
- **生命周期钩子**：`init(ctx)` 注入 llm-client、加载 recipe；
  `start/stop` 无长驻资源；`destroy` 显式声明无操作。

## 本部门校验域（10 的引用）

V-SCP-001 功能必填 / 002 无功能段删 / 003 beats 关键节点全覆盖 / 004 钩子前置 /
005 字数档位 ±10% / 006 术语密度匹配受众 / 007 禁信息倾倒三段连 /
008 教育科普类遵循 Mayer 四原则（分段/信号/一致/降噪）。
失败分级：001/002/003/004 为 error（阻断）；005/006/007 为 warn（进反模式统计）。

## 反例（编剧卷种子）

| 反模式 | 现象 | 根因 | 对策 |
|---|---|---|---|
| 信息倾倒 | 连续三段都是 inform，无情绪起伏 | 把讲稿当说明书写 | V-SCP-007 |
| 装饰口水段 | 段落不承担任何功能 | 凑时长 | V-SCP-002 |
| 钩子后置 | 前两段在铺垫背景 | 编剧顺序思维 | V-SCP-004 |
| 字数漂移 | 成片超档位 30% | 无视时长档位 | V-SCP-005 |

# 04-讲稿解析与字幕引擎-四层设计（domain/）

- **本质**：在"成片运行时"的时空约束下，本模块是把讲稿文本空间切分为分镜时间流、再按配音时长对齐帧窗的**切分对齐器**。
- **数据规范**：
  - DSL v2 契约（docs/03 §1）；type 枚举 12 值；`SCENE id|type|title` 开块、`=== narration` 分隔。
  - 校验规则：id 唯一、narration 非空、type 合法、table/panorama 须有表头、quote 须有 quote 字段——违规即 SchemaError（规则层运行时拦截）。
- **数据存储**：讲稿.md 是唯一源头（人写人审）；解析产物仅内存传递，gen.json 落盘由 application 负责。本模块无状态、纯函数。
- **数据流转**：
  - `parse_script(md, overrides)`：meta 解析（project.json 覆盖讲稿内嵌）→ 按 `\n## SCENE ` 切块 → 逐块提取 subtitle/bullets/rows/highlight/quote 等指令 → Scene 列表 + 结构断言。
  - `split_captions(narration, frames)`：按 `。！？；` 切句 → 按句长比例分配帧窗 → 末句对齐 frames。
  - `align_timeline(scenes, fps, tail)`：`frames = ceil(audioSec × fps) + tail`；tail=12（0.4s 呼吸）。
- **数据接口**：`parse_script() / split_captions() / align_timeline()` 三个纯函数；不 import infrastructure。
- **生命周期钩子**：init=parse+断言（空间开辟：Scene 列表）；start=align（时间流对齐）；stop=由 application 断言音频数；destroy=无（无自有空间，产物由上层落盘）。
- **基础子集**：title/bullets/flow/table/panorama/ending 六型为 DSL 的基础子集，仅用基础版式的早期格式讲稿零改动可解析。

# 工程部（M8 renderer + M9 state-engine：第一副导演 + 后期输出）

> 角色：第一副导演（计划与调度）+ 后期输出（渲染）| 上游：剪辑部（合成项目）|
> 模块：M8 + M9 | 校验域：V-STE-*、V-RND-* | 反例卷：工程卷

## 部门职责

工程部是全片的**时空管家**，管两件事：

1. **调度与生命周期**（第一副导演）：显式管理全流程空间开辟/回收
   （init/destroy）与时间流编排（start/stop + 主循环），把"视频编译"建模为
   可暂停、可恢复、可局部重放的事件驱动状态机——断点续跑、单镜重试、
   人工精修三大需求的共同根基；
2. **渲染与确定性**（后期输出）：把合成项目光栅化为成片，用版本锁定、渲染锁、
   输出校验三道闸门保证"同输入 → 同输出"。

## 理论锚点

| 理论/实践 | 转译 |
|---|---|
| 状态机理论 | 阶段/镜头双状态机 + 迁移白名单（非法跳转即错） |
| 调度理论（有界并发） | 调度批次 CONCURRENCY=3；云端内嵌轮询不占批次 |
| 崩溃恢复（幂等重放） | 任务执行前检查产物；在途任务超时重置重派 |
| 确定性渲染 | HyperFrames 时间轴可寻址；禁随机输入；锁版本 |
| 副导演现场纪律 | 停在途终态才收工（防半成品+僵尸进程） |

## 输入输出工件

- **输入**：剪辑部的合成项目 + 全流程 IR 状态。
- **输出工件**：调度日志（`logs/run.log`）、渲染报告、成片 `out/<title>.mp4`。
- 工程部不生产创意工件，但**守护所有工件的持久化与恢复**。

## 模块四层设计（M9 state-engine，runtime 核心）

- **数据规范**：
  - `Stage ∈ script|storyboard|sourcing|voice|compose|render|done`；
  - `ShotState ∈ pending|sourcing|sourced|voicing|voiced|ready|failed`；
  - 迁移白名单：pending→sourcing；sourcing→sourced/failed；sourced→voicing/failed；
    voicing→voiced/failed；voiced→ready/failed；failed→pending（仅 retry）；
    ready 终态。阶段迁移：init→script→storyboard→(确认事件)→sourcing→
    voice→compose→render→done；允许 retry --stage 回跳。非法抛
    `ERR_ILLEGAL_TRANSITION`；
  - `Task`/`RunEvent` zod schema。
- **数据存储**：状态真源 = `project.json`（经 M1 **原子写**：临时文件+rename，
  禁截断覆写）；事件日志 `logs/run.log`（append-only）；内存工作副本进程私有。
- **数据流转**：
  ```
  主循环（start 后）:
    drain_external_events()            # 改IR/加素材/retry/改风格 → 置脏
    if dirty: reload IR（schema 校验）
    actionable = select_actionable()   # 纯函数：
      sourcing 任务：state==pending
      voice 任务：state==sourced
      compose 任务：state==voiced
      确认门：storyboard→sourcing 需 confirm 事件
    if actionable 为空:
        全部 ready → done 停机
        有 failed 无 pending → 停机输出失败报告
        否则 → ERR_DEADLOCK 停机（绝不空转）
    batch = actionable.slice(0, 3)     # 有界并发
    dispatch → await 终态 → persist → advance

  断点续跑（init 制度化）:
    装载 IR 恢复状态（不重置）→ 停留在 sourcing/voicing 的在途任务
    检测"无活跃进程"→ 重置 pending 重派（幂等：产物已过则跳过）

  外部事件（时间流分支）:
    改 IR → 受影响镜头及下游状态一并回退（ready→voiced→sourced→pending）
    add-material → 导演部重算原 ask 镜的素材决策
    retry [--shot] [--stage] → 局部回跳
    确认表确认 → confirm 事件放行 sourcing
  ```
- **数据接口**：`run(p): RunReport`；`retry(p, shotId?, stage?)`；`status(p): StatusReport`。
- **生命周期钩子**：
  - `init(ctx)`：经 M1 装载 IR 恢复状态；按依赖正序初始化 M10→M2/M3→M4/M5/M6→M7→M8；
    环境 fail-fast（委托 M8.doctor）；
  - `start()`：启动主循环；
  - `stop()`：停止派发、等在途终态、经 M1 持久化、按依赖**逆序**停各模块
    （M8 先停释放渲染锁 → M5 停轮询 → 其余）；
  - `destroy()`：按依赖逆序回收（M8 临时目录 → M5 临时文件 → M1 句柄）；
    成片与 IR 永不回收；`clean` 是 destroy 回收策略的用户入口。

## 模块四层设计（M8 renderer）

- **数据规范**：`RenderSpec { width, height, fps, codec, outPath }`（来自 meta）；
  `RenderBackend` 接口（core）：`doctor()/preview(project)/render(project, spec)`
  ——**domain 只见接口不见实现**；`RenderCheck`（可解码/时长差 ≤ 时间线+500ms/
  分辨率帧率一致/非空）；hyperframes 精确版本锁定。
- **数据存储**：成片 `projects/<id>/out/<title>.mp4`（clean 永不删）；
  渲染临时目录（系统临时目录，clean 回收）；渲染锁 `projects/<id>/.render.lock`
  （文件锁）；`logs/render.log`。
- **数据流转**：
  ```
  render(p, spec?):
    ① doctor 前置（Node/ffmpeg/Chrome/版本；不过 → ERR_RENDER_ENV）
    ② 取渲染锁（被占用 → 等待或 ERR_RENDER_LOCKED）
    ③ npx hyperframes render（子进程，stdout/stderr 落日志）
       退出码非0 → 保留合成项目现场，重试 1 次 → 仍失败 failed + 现场路径
    ④ 输出校验（V-RND-003）：ffprobe + 时长比对 + 分辨率比对
    ⑤ 登记成片路径到 IR → persist → 释放锁
  ```
- **数据接口**：`doctor(): Check[]`；`preview(p): void`；`render(p, spec?): string`。
- **生命周期钩子**：`init(ctx)` 跑 doctor（fail-fast）、确认 hyperframes 版本；
  `start()` 取渲染锁；`stop()` 先终止在途子进程再释放锁；`destroy()` 回收临时目录
  （try/except 容忍）。
- **备用后端**：Remotion 适配器与 HyperFrames 适配器并列于 infrastructure；
  切换 = 换适配器 + 剪辑部 emitter 同步切换，domain 零改动（ADR-1/ADR-2）。

## 反例（工程卷种子）

| 反模式 | 现象 | 对策 |
|---|---|---|
| 截断覆写 IR | 残缺快照被当真源 | 原子写（临时+rename） |
| 无界并发 | 云端限流+资源耗尽 | CONCURRENCY=3 |
| 空转死循环 | pending 无法满足仍循环 | ERR_DEADLOCK 停机 |
| 状态隐式重置 | 重启丢进度 | 仅 retry/事件允许回退 |
| 在途不等待就停 | 半成品+僵尸进程 | stop 等在途终态 |
| 并发渲染 | 同项目两渲染互踩 | 渲染锁 |

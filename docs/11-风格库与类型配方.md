# make-video 风格库与类型配方（公共注册库）

> 本篇是**风格包与类型配方的唯一权威登记处**。消费者：导演部（04，风格决策与沉淀）、
> 编剧部（03，beats 与字数目标）、美术摄影部（05，tokens/motion/effects 注入）、
> 采购部（06，风格相关素材公式）、声音部（07，声线与音效策略）、剪辑部（08，
> pacing/transitions/grade 校验）。
> 三层架构：规范（10，笼子）→ 风格包（本篇，口音）→ 类型配方（本篇，场景组装）。

## 一、三层架构 recap

| 层 | 实体 | 职责 | 目录 |
|---|---|---|---|
| 规范（笼子） | V-* 不变量 | 什么不许做 | `src/core/validators/` |
| 风格包（口音） | `style.json` 参数包 | 审美取向 = 参数空间一个点 | `styles/<id>/` |
| 类型配方（场景） | `recipe.json` + 节拍 + 标杆 | 需求类型的完整配置 | `recipes/<genreId>/` |

风格包与配方均为**只读共享库**，项目经 `project.json` 的决策记录引用，不拷贝。

## 二、风格包 schema（styles/<id>/style.json）

```json
{
  "id": "comedy-pop",
  "name": "周星驰式无厘头",
  "grade": "A",
  "status": "registered",
  "userFacing": {
    "name": "周星驰式无厘头",
    "aliases": ["无厘头", "星爷风格", "喜剧风"],
    "vibe": "一本正经地荒诞：庄重形式 × trivial 内容；破功要有真心",
    "bestFor": ["comedy-sketch", "science-explainer(辅)"]
  },
  "anatomy": {
    "script": "三翻四抖结构；双声线写作；小人物崇高公式",
    "directing": "对位加'戏仿'模式；庄重形式×trivial内容；破功点标注",
    "art": "鲜艳俗艳色板；toneJump 破功跳色；漫画符号槽位",
    "camera": "heroic low angle；smash zoom 落反应；慢动作+骤然常速",
    "performance": "定格/反应弹入/破第四面墙/极端挤压/冲击震动",
    "sourcing": "用户素材→戏仿构图公式；音效梗库",
    "sound": "双声线逐镜切换；唱片急停；怀旧金曲",
    "editing": "硬切优先；comedy-beat 曲线；梗落点四联动"
  },
  "palette": {
    "primary": "#...", "accent": "#...",
    "neutral": ["#...","#...","#...","#...","#..."],
    "colorArc": "curiosity→wonder→concern→hope"
  },
  "type":     { "families": ["sans-a","sans-b"], "scale": {"title":0.10,"body":0.035}, "tracking": {"title":-0.02} },
  "layout":   { "density": 0.45, "maxElementsPerShot": 3, "whitespace": 0.30 },
  "motion":   { "easing": "ease-out-expo", "intensity": 0.7, "staggerMs": 70, "spring": {"stiffness":180,"damping":20} },
  "pacing":   { "curve": "three-act", "shotLenMs": [1500,3000], "breathEvery": 5 },
  "effects":  { "grain": 0.08, "vignette": 0.15, "letterbox": false, "dof": 6, "bloom": 0.20 },
  "transitions": ["dissolve","whipPan"],
  "shotScaleBias": ["MS","CU"],
  "provenance": {
    "source": "absorbed|manual",
    "from": "参考来源说明（用户描述/参考视频特征）",
    "version": "1.0",
    "absorbedAt": "...",
    "review": "对拍结论摘要"
  },
  "references": "references.md",
  "antiPatterns": "anti-patterns.md"
}
```

**三个新段的用途**：

- **`userFacing`**：用户叫法词典——用户说"周星驰那种"→ 命中本包。`aliases` 是
  同义词，`vibe` 是一句话气质，`bestFor` 是适合的类型。**这是用户语言与参数空间
  之间的翻译层**（SKILL.md 的风格菜单由它生成）。
- **`anatomy`（按部门键）**：风格的**部门指令集**——每键标注消费部门（见第八节
  矩阵）。双用途：① 给用户看的可解释解剖卡（A13）；② 给各部门的生成约束
  （人类可读的元素清单比裸参数更不易让 LLM 跑偏）。
- **`provenance`**：沉淀档案（A14）——来源、版本、grade、对拍结论。手工包
  `source=manual`，沉淀包 `source=absorbed`。**必填**（V-STYLE-006）。

## 四、v1 风格选单与组合纪律

### 4.1 v1 上架

`keynote-minimal`、`kurzgesagt-explainer`、`bass-graphic`、`anderson-symmetry`、
`noir-contrast`、`comedy-pop`（无厘头样板，随表演原语一起建）。
v1.5 增补：`classical-continuity`、`talking-head-punch`。
其余为规划，未对拍不上架。

### 4.2 组合三级纪律（对应 V-STYLE-*）

| 级别 | 路径 | 条件 |
|---|---|---|
| L1 recipe 预绑（常规） | 直接用配方验证过的组合 | 无额外条件；谱系 = recipe |
| L2 参数层 override | base 包 + 覆写参数组（如 base=explainer，effects 取 noir） | 过一致性校验器：色板同家族/运动强度不越区间/转场在词表/字体 ≤2/effects 兼容 |
| L3 自由组合（逃生舱） | agent 自选参数拼装 | 仅当 recipe 明显不适合；必须校验 + 必须用户确认 |

**无默认风格**（V-STYLE-001）：每次必须带 `source` + `rationale`；
agent 无法论证 → 进确认表（A4）询问。组合谱系记入 IR。

## 五、组装公式与示例（新需求如何拼出来）

**公式：成品 = recipe（结构）× style（部门指令）× override（参数覆写）**

```
用户: "做个迪士尼风格的童话短片"
 ① recipe = story-narrative（三幕+故事弧）
 ② style  = pixar-2d（base，用户叫法命中）
 ③ override（L2，过一致性校验器）:
    - effects   ← ghibli-painterly 借"水彩纸感"（grade 保持 B）
    - motion.intensity ← 上调（黄金时代歌舞段的弹性）
    - sound     ← 歌舞节拍（每拍一切；beats 不可用时退化承转合）
 ④ anatomy 部门指令随之确定:
    编剧部: 童话 beats（愿望/伙伴/试炼/归来）
    导演部: 对位=emotion 为主；批注写"参考黄金年代表情符号"
    美术:   圆形形体语言（圆=友善，尖=对立）+ 色彩脚本随情绪弧
    摄影:   MS/MCU 为主（童话要看清表情）+ 柔光
    表演:   极端弹性 + anticipation 放大（十二原则全面上调）
    声音:   管弦乐弧 + 角色声线
    剪辑:   匹配剪辑优先 + 歌舞段卡点
 ⑤ 决策写入 IR（style.source=agent-chosen + rationale + 组合谱系）
```

**匹配优先原则**：新需求先问“像不像已有包/配方”——像就 override，不像才 absorb。
系统是**生成式**的，菜单无需穷尽电影史。

## 六、类型配方（recipes/<genreId>/recipe.json）

每类配方字段：`beats[]`（结构节拍，**锚定编剧理论**：叙事类用 Syd Field 三幕 +
Save the Cat 节拍映射，喜剧类用三翻四抖，信息类用"钩子-展开-收束"注意力结构，
**教育/科普类必须遵循 Mayer 四原则**——分段（章节标记）/信号（关键词高亮）/
一致（旁白画面同现）/降噪（禁装饰元素），见 V-SCP-008）、
`directorialNotes[]`（导演批注模板：每 beat 的视觉意图/情绪目标/参考气质/对位模式，
M3.writeDirectorNotes 的约束输入）、`style`（推荐组合，L1）、
`pacing`（曲线 + 镜长区间，按时长档位分档）、`density`、`subtitles`（策略）、
`headTail`（片头尾模式）、`sound`（BGM 情绪弧 + 音效集 + 声线策略）、
`templates`（偏好模板集；图表模板遵循 Tufte 数据墨水，见 V-CHT-*）、
`durationTiers`（三档位变体）。

### 6.1 八类配方总表

| genre | 结构节拍 | 推荐风格组合（L1） | pacing 基线 | 密度 | 字幕策略 | 片头尾 |
|---|---|---|---|---|---|---|
| science-explainer 科普讲解 | 钩子→概念→机制→案例→总结 | kurzgesagt / vox | 中速 2-3s | 高 | 关键词高亮（Mayer 信号） | 订阅引导尾 |
| story-narrative 故事叙事 | 三幕 + 故事弧 | shinkai / ghibli | 慢，呼吸镜多 | 低 | 少而精 | 情绪收束 |
| product-promo 产品说明广告 | 痛点→方案→特性×3→CTA | keynote-minimal | 停顿式一屏一事 | 中 | 特性卡 | 强 CTA 尾 |
| tutorial-howto 教程 | 目标→步骤×N→检查点 | keynote / bass | 匀速 + 进度指示 | 中高 | 步骤编号常驻 | 成果展示尾 |
| news-brief 新闻资讯 | 头条→要点×N→展望 | bass / cyber | 快 1.5-2s | 高 | 卡片式 | 台标尾 |
| opinion-essay 观点演说 | 立论→论证×3→金句收尾 | bass-graphic | 中慢，金句定格 | 低中 | 大字金句卡 | 互动提问尾 |
| documentary-mood 纪录氛围 | 时空→群像→细节→升华 | ghibli / shinkai | 极慢（借 tarkovsky-pacing） | 低 | 极少 | 留白尾 |
| kids-education 儿童教育 | 角色引入→探索×N→儿歌总结 | pixar-2d | 慢速清晰 | 低 | 大字号高对比 | 角色挥手尾 |

### 6.2 时长档位变体（所有配方共享的参数轴）

| 档位 | 结构 | pacing | 旁白字数目标 | BGM 弧 | 字幕 |
|---|---|---|---|---|---|
| 0-5 min | 钩子前置，单章节 | 镜长 1.5-3s | ~130 字/min | 单弧 | 常驻精简 |
| 5-10 min | 完整三幕，2-4 章节标记 | 镜长 2-4s | ~150 字/min | 起承转合 | 关键词高亮 |
| 10 min+ | 多章节 + 回顾锚点 + 慢燃入场 | 镜长 3-6s | ~160 字/min | 长弧 + 章节变奏 | 章节标题卡 |

档位是配方的一等参数：`init --duration-tier` 选择，影响节拍表实例化、
编剧部目标字数（V-SCP-005）、剪辑部时间线密度校验（V-RHY-003）。

## 七、分类轴（库外需求的归类法）

导演部对不在八类内的需求，按六轴归类 → 最近 recipe + 参数覆写：

| 轴 | 取值 | 影响 |
|---|---|---|
| 信息密度 | 低↔高（图表/数据占比） | density、模板集、镜长 |
| 叙事强度 | 弱（清单）↔强（故事弧） | beats、pacing 曲线 |
| 意图极性 | 告知 / 说服 / 教学 / 娱乐 | headTail（CTA/总结）、语气 |
| 情感基调 | 冷峻 / 温暖 / 紧张 / 昂扬 / 荒诞 | palette.colorArc、BGM 弧 |
| 受众专业度 | 大众 / 进阶 | 术语密度（V-SCP-006）、字幕策略 |
| **时长档位** | 0-5 / 5-10 / 10+ | 见 6.2 |

- 落在两类之间（如"科普+故事"）= **混合 genre**：主 recipe + 辅 recipe 覆写，
  与风格组合同机制（L2 级，过校验器）。
- 六轴都归不类 → 问用户，给最近 2 个候选 + 各自一句话差异说明。
- 用户直接给参考视频/图片 → 走风格沉淀（第八节），不走分类轴。

## 八、风格沉淀流水线（style absorb，导演部）

### 8.1 三层沉淀模型（风格知识不每次重推）

| 层 | 沉淀什么 | LLM 何时介入 |
|---|---|---|
| T1 制度 | 吸收的方法：部门制/工件链/校验器/对拍门禁/匹配优先（风格无关） | 从不 |
| T2 内容 | 每个注册风格的部门指令集（参数 + anatomy + 反例） | 从不——生成期读登记指令（V-STYLE-007） |
| T3 感知 | 新风格吸收时的理解 | **仅一次**：按 anatomy 部门键表格填空，可审可改 |

### 8.2 五步流程

```
absorbStyle(p, source):
  ① 输入解析：参考视频（ffmpeg 抽帧）/图片/文字描述；
     agent 多模态分析（本会话 vision 模型；不可用则用户口述补齐）
  ② 匹配优先：与既有风格包按特征比对
     → 高度相似 → 建议 base+override（防风格库爆炸）
     → 差异显著 → 按 anatomy 部门键 schema 生成草稿包（status=draft）
  ③ 解剖填空与确认：展示 A13 解剖卡给用户确认/修正（status → candidate）
  ④ 小样对拍：草稿包渲染测试片 vs 参考帧并排 review
  ⑤ 上架：达标 → status=registered（评 grade，初评多 B）→ A14 归档；
     不达标 → 迭代参数或淘汰（记反模式）
```

**匹配优先原则**：用户给参考时，先问"这像不像已有的某个包"——像就走 override，
不像才新建。防止风格库膨胀成垃圾场。

### 8.3 版权纪律

沉淀提取的是**语法**（构图关系/色彩关系/节奏结构），不是素材：参考帧只进本地
对拍目录，**禁止任何参考帧进入成片**；references 只存解剖描述 + 用户自有参考
缩略图。提取自第三方作品的风格包，provenance.from 必须如实标注。

### 8.4 grade 评定规则

| grade | 条件 |
|---|---|
| A | 手工建设或沉淀后经过完整对拍，全部门指令齐备且可复现 |
| B | 调性可复现但工艺边界明确（如氛围层可、绘制工艺不可）；或初轮对拍部分达标 |
| C | 仅 pacing 参数可用 |

## 九、部门 × 风格消费矩阵（anatomy 部门键的归口）

| 部门 | 消费 style 字段 | 消费 anatomy 键 | 校验域 |
|---|---|---|---|
| 编剧部 | （经 recipe）beats/声线策略 | `anatomy.script` | V-SCP-* |
| 导演部 | style 组合决策、transitions 词表（参考） | `anatomy.directing` | V-STYLE-*、V-CP-* |

## 十、配方与风格的生命周期

```
v1 手工建设（六风格 × 八配方，各带 references + anti-patterns）
   │
   ▼
标杆对拍（每组合渲染测试片，与 references 并排 review；B 级按 B 级标准）
   │
   ▼
反模式喂料（validation.log 的 warn 聚类 → 各配方/风格 anti-patterns.md 增补，
             按部门归档见 02）
   │
   ▼
用户驱动沉淀（style absorb：参考素材 → 匹配优先 → 解剖填空 → 对拍 → 上架）
   │
   ▼
recipe-save（P2）：用户认可的好项目 → 沉淀为新 recipe（结构+组合+pacing 固化）
   │
   ▼
社区生态（远期）：风格包/配方/模板的分发与版本兼容矩阵
```

# make-video 架构总览（工程地图）

> 本篇是**过程视角的家**：电影部门制（02-09）在工程上的投影——分层、数据流、
> 技术选型、ADR、CLI 契约、测试策略。各部门模块的递归四层与生命周期钩子在
> 03-09；公共法律在 10；公共注册库在 11。

## 一、分层架构图（过程视角）


**依赖方向铁律**：interfaces → application → runtime → domain ← infrastructure，
所有箭头最终服务于 runtime/ 的调度闭环；domain 与 infrastructure 之间只允许
经 core/ 接口的依赖注入，禁止具体实现反向渗透。

## 二、数据流（一次完整编译 = 各部门协作）

```
init:  topic + options ──▶ projects/<id>/ 脚手架 + project.json(schema版本)
script(编剧部):    topic ──LLM──▶ Script{fullText, segments[]}（带功能标注）
storyboard(导演部): segments ──导演批注──▶ shots[] + 素材决策 + 风格决策
           ──▶ 确认表（用户一次确认）──▶ IR 落盘
sourcing(采购部):  per shot 按 kind 分派 ──▶ scenes/*.html | materials 归一化 | assets 落盘
voice(声音部):     per shot 旁白 ──TTS/录音──▶ audio/vo/*.mp3 + ffprobe 实测时长
compose(剪辑部):   ready 集 ──V-*校验──▶ Timeline + remotion/ 合成项目
render(工程部):    remotion/ ──hyperframes render──▶ out/*.mp4 ──输出校验──▶ done
```

每个阶段的状态迁移都先持久化再派发下一任务（崩溃只丢在途任务，不丢状态）。
happy path 时序（含导演批注插入）：

```
用户: make-video init "黑洞是怎么形成的" --duration-tier 5-10
 CLI→runtime.init→M1 开辟项目→M10 加载库→(暂停: 询问确认时长档位/genre? 已给则跳过)
用户: make-video run
 M2 编剧→讲稿分段（每段带功能标注）
 M3 导演: writeDirectorNotes→导演批注（每段视觉意图/情绪目标/对位模式）
 M3 分镜: 以批注为约束→recipe实例化→LLM分镜→素材决策(全code)→风格决策(explainer,有依据)
   → buildConfirmation 输出确认表（含批注摘要）→ (暂停等用户确认)
用户: 确认（或改表）
 M5 逐镜 draw→sourced（有界并发3）
 M6 逐镜 TTS→voiced（实测时长）
 M7 validateReadiness(全绿)→continuityReport→时间线→remotion/合成项目
 M8 doctor→render→输出校验→out/*.mp4→done
```

## 三、技术选型（含时空理由）

| 选型 | 决定 | 时空理由（选型如何满足时空需求） |
|---|---|---|
| 语言/运行时 | **TypeScript on Node 22+** | 规则：编译期类型系统强制 IR/schema/接口契约（第一道规则拦截）；空间：Node 单进程+子进程与"有界并发轮询"时间流天然匹配；HyperFrames 要求 Node 22 |
| 渲染后端 | **HyperFrames**（主）/ Remotion（备，经 `RenderBackend` 接口隔离） | 时间：时间轴可寻址 → 确定性渲染，同输入同输出，契合可重放可重试；空间：静态 HTML/CSS/GSAP 无打包步骤，依赖最轻；规则：agent-native——LLM 生成 HTML 比 React 组件幻觉率低，场景生成成功率即流水线成功率 |
| 场景媒介 | **HTML/CSS/GSAP + 内联 SVG** | 空间：矢量任意分辨率；web 标准即 DSL 无锁定；规则：模板骨架+数据注入+属性校验三层防御替代编译期拦截 |
| CLI 框架 | **commander** | 接口层薄封装，零业务逻辑；命令契约即 interfaces/ 的对外形状 |
| Schema/校验 | **zod** | 规则：IR/风格包/配方/校验器输入全部 schema 化，运行期强制；错误信息中文化 |
| 媒体操作 | **ffmpeg / ffprobe（系统级，doctor 体检）** | 空间：素材归一化（裁剪/变速/帧率统一）、时长测量（时间真源）；抽帧导入 |
| TTS | **edge-tts 协议 Node 实现**（provider 接口；备选：本地 Kokoro、HeyGen/ElevenLabs） | 时间：旁白时长是时间真源，TTS 必须可重复、可测速；空间：音频落项目目录隔离；"最节省"主线默认免费线路 |
| 云端生成桥 | **buddy-cloud.py 子进程**（video/image/video-fx） | 空间：不重造生成能力，Python 进程边界隔离；规则：每次调用经 `connect_cloud_service` 取新凭证，禁缓存复用 |
| LLM 客户端 | **llm-client 抽象**（agent 会话内执行优先；无会话走配置 endpoint） | 时间：LLM 任务是状态机中的普通任务（可重试/可断点）；规则：输出必须过 schema 校验，失败重试上限 |
| 测试 | **vitest** | P/Q/I 验证落地；标杆对拍用快照对比 |
| 日志 | 轻量自研（fs append + 级别） | 空间：logs/ 落项目目录；禁重依赖 |

## 四、关键架构决策记录（ADR-lite）

| # | 决策 | 理由 | 被否决的替代 |
|---|---|---|---|
| ADR-1 | HyperFrames 为首选渲染后端，Remotion 备用 | agent-native + 依赖轻 + 时间轴模型与 shot IR 同构（data-start/duration/track-index 直接由剪辑部生成） | Remotion 为主：依赖重、LLM 生成 React 场景幻觉率高 |
| ADR-2 | 渲染后端经 `RenderBackend` 接口适配 | 版本迭代快（0.4→0.8），适配层隔离漂移风险；保留切换自由 | 直接依赖 hyperframes API |
| ADR-3 | `project.json` 为唯一状态真源，原子写（临时文件+rename） | 状态机断点续跑的前提；禁截断覆写防残缺快照 | 多文件分散状态 |
| ADR-4 | 素材按项目目录隔离，共享库只读 | 从结构上排除跨项目串音/覆盖 | 共享 assets 目录 |
| ADR-5 | LLM 驱动阶段（编剧/导演批注/场景生成）与确定性阶段（voice/compose/render）分离，前者经 llm-client 走状态机任务 | LLM 不确定性被状态机的重试/断点/人工精修吸收 | 全自动黑盒 pipeline |
| ADR-6 | 规范/风格包/类型配方三层分离 | 规范是不变量（笼子），风格是参数点（口音），配方是场景组装（可复用）；无默认风格防 agent 偷懒 | 单一"风格"概念混层 |
| ADR-7 | 分镜前一次确认（素材决策表 + 风格决策 + 导演批注摘要一张表） | 混合工作流要求人提供判断输入，但拒绝每镜询问的交互灾难 | 全自动不问 / 每镜都问 |
| ADR-8 | 依赖精确锁版本（lockfile 提交） | 渲染栈（Chrome+FFmpeg+框架）对版本敏感，浮动范围 = 不可复现 | 语义化版本范围 |
| ADR-9 | **角色工件化交接**（02 职能视角的制度核心） | 电影前置制作的第一危险是"翻译损耗"（剧本→分镜→镜单意图漂移）；LLM 流水线每次模型调用都是一次翻译。对策：每个部门交接处强制留下工件（导演批注/shot list/连续性报告/混音计划），工件是契约+质检对象+人工精修抓手 | 无工件的"阶段直连"（意图黑盒流转） |
| ADR-10 | **文档与代码按电影部门制组织**（02-09） | "做视频的本质是像拍电影那样思考"：角色视角是主干（谁对什么质量负责、依据什么理论），过程视角降为投影（工程地图=本篇）。模块即部门的实现，四层模型成为部门内部规格 | 按技术分层组织文档（过程视角主导，角色视角沦为补丁） |
| ADR-11 | **风格沉淀三层模型 + 匹配优先** | T1 制度（部门/工件/校验器，风格无关）已沉淀；T2 注册风格 = 部门指令集，生成期读指令执行（V-STYLE-007，防漂移+降成本+保可解释）；T3 新风格吸收时 LLM 只按 anatomy 部门键表格填空一次（可审可改）。匹配优先（相似先 override）防风格库爆炸 | 每次生成都让 LLM 自由"理解"风格（漂移+成本+不可解释）；用户说什么都新建包（库爆炸） |

## 五、项目脚手架与运行环境

### 脚手架

项目通过 `project.json.style`（决策记录）与 `project.json.recipe`（genre 实例）
引用只读库中的风格包与配方；库文件从不拷贝进项目（保证全项目升级一致）。

```
projects/<project-id>/
├── project.json          # 中央 IR：meta + script(+功能标注) + directorNotes + shots[]（含状态/决策）
├── scenes/               # 代码绘制的场景（LLM 生成、人可精修）
│   ├── Scene_s01.html
│   └── shared/
├── materials/            # 用户素材（录音/照片/视频）+ index.json
├── assets/               # 导入/云端素材，按镜分子目录
├── audio/                # 旁白 + BGM + 音效
├── out/                  # 成片 mp4
├── logs/                 # run.log / compose.log / render.log / validation.log
└── remotion/             # HyperFrames 合成项目（剪辑部生成）
```

### 运行环境

| 组件 | 要求 | 体检方式 |
|---|---|---|
| Node | ≥ 22 | `make-video doctor` |
| ffmpeg / ffprobe | 系统 PATH 可达 | `make-video doctor` |
| Chrome | HyperFrames bundled（或系统 Chrome） | `make-video doctor` |
| 云端凭证 | 仅 cloud 路径需要，每次 `connect_cloud_service` 新取 | doctor 提示可选 |
| TTS 线路 | edge-tts 默认（网络可达）或本地 Kokoro | doctor 探测 |

## 六、CLI 契约（interfaces/）

```
make-video init <topic> [--aspect 16:9|9:16] [--duration-tier 0-5|5-10|10+]
                    [--genre <id>] [--style <id>] [--script <file>]
                    [--materials <dir>] [--asset-policy auto|ask|code-first|real-first]
make-video doctor
make-video add-material <file|dir> [--project <id>] [--shot sXX] [--tags a,b]
                    [--url <来源页>] [--license <许可>] [--credit <署名>] [--strict]
make-video material-plan [--project <id>] [--style <id>]   # 逐镜素材需求单 → gen/material-plan.json
make-video storyboard [--project <id>]        # 导演批注 + 分镜 + 输出确认表
make-video draw [--shot sXX] [--project <id>]
make-video import --shot sXX --from <file|project> [--project <id>]
make-video voice [--shot sXX] [--from <file>] [--project <id>]   # MV_TTS=edge-py|edge|silent|sovits
make-video compose [--project <id>]
make-video render [-o out.mp4] [--project <id>]
make-video run [--project <id>]               # 全自动（含确认点暂停）
make-video status [--project <id>]            # 阶段/镜头/素材缺口/风格决策/部门验收门
make-video retry [--shot sXX] [--stage XX] [--project <id>]
make-video clean [--project <id>]
make-video confirm [--allow-ai] [--project <id>]   # 确认分镜表；--allow-ai 授权云端生图
make-video recipe-save [--project <id>]       # P2：好项目沉淀为新配方
make-video style list [--grade A|B]           # 风格菜单（用户叫法索引）
make-video style show <id>                    # 解剖卡（anatomy 部门指令集）
make-video style absorb --from <视频|图片|描述> # 新风格沉淀（五步流水线，导演部）
make-video style promote <id>                 # candidate → registered（对拍通过后）
```

约定：所有命令输出中文；`--project` 缺省取当前目录推断或唯一项目；
长任务输出进度到 stderr，结果 JSON 到 stdout。

## 七、错误处理与重试策略总览

| 失败类 | 检测点 | 策略 |
|---|---|---|
| LLM 输出非法 | schema 校验 | 带错误反馈重试（上限 3），超限标记 failed 并保留原始响应供人工 |
| 云端生成失败 | 轮询终态 FAIL | 指数退避重试（上限 3），超限 failed |
| TTS 失败 | 合成异常 | 换 provider 重试 1 次，再失败 failed |
| 素材缺失 | compose 前 V-* 校验 | **阻断**并输出缺口清单（哪些镜缺什么） |
| 音画不同步 | compose 时长对齐校验 | 阻断（不允许带病渲染） |
| 渲染失败 | hyperframes 非零退出 | 保留合成项目现场，重试 1 次；再失败 failed + 现场路径 |
| 状态机非法跳转 | 迁移表白名单 | 抛 `ERR_ILLEGAL_TRANSITION`，记日志，进程级 fail-fast |

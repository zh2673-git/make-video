# 13 — 优化落点地图（改哪里有用，改哪里没用）

> 本文回答一个具体问题：**看到别人的优秀视频/开源项目，想"把那个东西吸收进来"，该改哪个文件？**
>
> 判据不是"哪个文件名字像"，而是三件事：这条改动**对哪条出片路径有效**、**要连带改几处**、
> **改错了会不会静默退化**。三者合起来才是收益。
>
> 权威数字一律不手写：跑 `make-video capability`（加 `--json` 拿完整名单）。
> 本文只讲**结构与判据**，具体数量交给命令与 `tests/catalog.test.ts`。

---

## 一、先认清三条出片路径（收益大小的根源）

同一处改动，对不同路径的价值差一个数量级。这是本图最重要的一栏。

| 路径 | 触发条件 | 谁在画场景 | 特征 |
|---|---|---|---|
| **P-agent** | 默认（SKILL 铁律 8：逐镜手写 HTML） | agent 自己写 HTML/CSS/GSAP | **最自由**，不受原语/语法强制 |
| **P-llm** | 确认点选 LLM 画（`drawScene`） | LLM 生成，校验器把关 | 受**原语词表 + 语法骨架**硬约束 |
| **P-forge** | 无 LLM 兜底（`adoptScene`/forge） | `templates/scenes/*.html` 填充 | 只有模板池与语义 cues 起作用 |

**关键事实（决定排序）**：`V-MOT-023`（语法必选原语）**只在 P-llm 强制**——
`scene-forge.ts` 的 `enforceActionSheet` 仅由 `drawScene` 的 LLM 分支传入，
`adoptScene` 路径不传。所以：

> **扩充语法骨架 = 只对 P-llm 有效；对主力路径 P-agent 基本无效。**
> 这推翻了「11 种骨架 → 20 种比 26 个词 → 50 个词划算得多」的一半。

## 二、六层落点 × 三条路径（收益矩阵）

★ 数量 = 收益大小；「连带」= 要同时改几处才不漂移。

| 落点 | 唯一事实源 | P-agent | P-llm | P-forge | 连带 |
|---|---|---|---|---|---|
| **L1 词汇** 动效原语 | `core/validators/scene.ts` `MOTION_WHITELIST` + `templates/motion/motion-lib.js` | ★★（缺的是构图不是动词） | **★★★**（唯一动词表） | ★★ | 4 处 |
| **L2 骨架** 镜头语法 | `domain/motion-grammar.ts` `GRAMMARS` | ★（不强制） | **★★★**（硬骨架） | ★ | 3 处 |
| **L3 观感** 风格包 | `styles/*.json` `visuals` | **★★★** | **★★★** | **★★★** | 2~3 处 |
| **L4 形态池** 模板 | ①`recipes/*.json` `templates` ②`TEMPLATE_CUES` ③`templates/scenes/*.html` | ★★（仅①②）／③**零** | ★★（仅①②）／③**零** | **★★★** | 3 段各自独立 |
| **L5 预算** 审计判据 | `motion-grammar.ts` `auditMotionMix` / `accent-budget.ts` | **★★★**（闸门松紧） | **★★★** | **★★★** | 2 处 |
| **L6 句法** HTML/CSS/时序 | 无池子，完全交给作者 | **★★★** | × | × | 0 |

### 性价比排序（按"总收益 ÷ 改动连带成本"）

1. **L3 风格包 visuals** — 三路径全高，连带仅 2~3 处（schema 通常已够用）。**改这里几乎从不亏。**
2. **L5 预算判据** — 直接决定成片质感（"动效语法"案例里 3.7%→26.5% 的差别就是它抓出来的），
   改动小（一个常量 + 一条审计条款）。
3. **L1 原语** — 对 P-llm 决定性，连带 4 处，且**必须**过 `tests/catalog.test.ts` 的双向断言。
4. **L2 语法** — 对 P-llm 决定性，但连带 3 处，其中 2 处以前是静默回退（现已改显式告警）。
5. **L4 模板文件（③）** — 只救 P-forge 兜底。**吸收外部项目时最常被误判为高收益的一层。**

## 三、判定速查表（外部参考 → 该改哪层）

```
外部项目给了什么？
│
├─ 一种「新的画面运动语义」，现在画不出来
│   → L1 词汇。先查 motion-lib 是否已有同义分支（drift vs pan 就是易混对），有就别加。
│
├─ 一种「这段在讲什么 → 该怎么画」的新套路
│   → L2 语法。先问 REQUIRED_BY_GRAMMAR 的现有骨架能否承载；
│     能承载就只调 cues/cameraBias（不改骨架），成本降一半。
│
├─ 一种观感 / 配色 / 画材 / 质感（"看起来像那个片子"）
│   → L3 风格包 visuals。最便宜，优先做。
│
├─ 一个新的版面结构 / 版式母题
│   → L4，但要分清是三段里的哪一段：
│     只改 scenes/*.html     → 仅 P-forge 受益
│     改 TEMPLATE_CUES       → 三条路径的"语义→模板"选型都受益
│     改 recipes.templates   → 候选池变了，三路径都受益
│
├─ 一条「别让片子退化成 X」的判据（"别全是推镜"、"别全屏是字"）
│   → L5。加 V-* 条款进 docs/10 + 落到 auditMotionMix。
│
└─ 纯手工技法（某镜的构图手法、某段时序）
    → L6。写进场景 HTML 即可，不进任何池子——**不要为了一镜加原语**。
```

### 每层动手前必须回答的两问

1. **连带改了几处？** 漏一处的后果是"静默退化"（走 else 分支 / 静默回退默认值），
   画面看起来正常但你要的效果没发生。对照第二节「连带」列。
2. **会不会撞 L1？** 凡是"新动作"都可能要动 `ACCENT_PRIMITIVES`（重音预算 1/3）。
   加了重音原语却没进 `ACCENT_PRIMITIVES`，等于给了一条绕过预算的后门。

## 四、四个防腐机制（让这张图不腐烂）

地图是文档，文档会腐烂——本项目已发生过三次同类事故（白名单漏 `drift`、文档写"九种语法"
实为 11、SKILL 风格菜单 16 条实际 9 包）。所以收益地图必须配**机制**，不能靠自觉。

### ① 单一事实源 `src/core/catalog.ts`

原语名单曾有 5 份引用点（白名单／motion-lib 实现／composer 的 `hasMain` 正则／
语法骨架表／文档数字）。现在：

- `NON_ACTION_PRIMITIVES`：不算主动作的 7 个（装配/字幕/机位/收尾/待机/母题循环）
- `MAIN_ACTION_PRIMITIVES` = 白名单 − 非主动作 → `composer.ts` 的 `MAIN_ACTION_RE` **派生**自这里
- `GRAMMAR_IDS` 从 `GRAMMARS` 派生
- `buildCapability()` 输出能力清单

> **`drift` 归入主动作**：它是刻意选择的匀速慢移（v1.1.1 专为氛围镜加的），
> 与"没填机位"不同——`static`/`none` 才是真的不动。

### ② `make-video capability [--json]`

优化前先跑它。想知道"现在有多少东西可改、都在哪"，不用翻代码。

```bash
make-video capability          # 摘要：数量 + 风格包清单 + 语法 id
make-video capability --json   # 完整：原语/主动作/非主动作/重音/语法骨架/机位词
```

### ③ `tests/catalog.test.ts` 的 14 条防腐断言

| 组 | 钉住什么 | 对应真实事故 |
|---|---|---|
| ① 白名单 ↔ motion-lib | 双向包含（有词无实现 / 有实现无词）；主动作名单闭合；`hasMain` 不再手写正则 | 白名单加 `drift` 后 `hasMain` 未跟 |
| ② 语法 ↔ 骨架/收势 | 每语法都有 `REQUIRED_BY_GRAMMAR` 与 `SETTLE_BY_GRAMMAR`；无幽灵条目；骨架原语必在白名单且必含 `motifLoop`；机位词与 motion-lib if 分支一致 | 新语法漏登记静默退化 |
| ③ 文档 ↔ 实际 | 「N 种语法」「N 个原语」的 N 必须等于实际值；菜单点名的风格 id 必须真实存在；真实风格包必须都被菜单收录 | "九种语法"/"12 个原语"/16 条幽灵菜单 |

### ④ 静默回退改显式告警

`REQUIRED_BY_GRAMMAR` / `SETTLE_BY_GRAMMAR` 缺项以前是 `?? 默认值` 悄悄兜底——
新语法会得到"只有 motifLoop"的最松骨架且无人知晓。现改为 `console.warn`（同语法同项只告警一次），
不阻断出片但一定留证，配合 ③ 的覆盖断言在 CI 阶段就红。

## 五、各层改动清单（怎么改，按它做不会漏）

### L1 加一个动效原语

1. `templates/motion/motion-lib.js`：`MV.newPrim = function (sel, opts) {...}`
2. `core/validators/scene.ts`：`MOTION_WHITELIST` 加 `'MV.newPrim'`
3. `core/catalog.ts`：**判断**它算不算主动作（算就不进 `NON_ACTION_PRIMITIVES`）；
   若它是"标点"还要加进 `ACCENT_PRIMITIVES`
4. `docs/10` §5.3：登记动机与用法（重音类必须说明预算影响）
5. 跑 `tests/catalog.test.ts` —— ①②组会双向校验，漏一步就红

### L2 加一种镜头语法

1. `domain/motion-grammar.ts`：`GRAMMARS` 加一项（`cues`/`when`/`avoid`/`motionBeats`/`cameraBias`/`textShare`/`motifs`）
2. 同一文件：`REQUIRED_BY_GRAMMAR` + `SETTLE_BY_GRAMMAR` **必须同时登记**（漏了会告警）
3. `pickGrammar` 的打分权重是否需要调（新语法的 cues 会不会抢太多）
4. `docs/10` §5.3 语法表 + SKILL.md 的语法计数（有断言守着）
5. `tests/motion-grammar.test.ts` + `tests/catalog.test.ts` ②组

### L3 加一个风格包

1. `styles/<id>.json`：`id`/`grade`/`status: registered`/`userFacing`（名字+aliases）/`anatomy`/`visuals`
2. `docs/11` 风格表登记；`SKILL.md` 风格菜单加一行（有双向断言守着）
3. `registry.load()` 会 `StylePackSchema` 校验，不符直接抛 `STYLE_INVALID`
4. **注意 `visuals.dimension`（2d/css3d/mixed）**：决定机器是否允许 3D 痕迹（V-STYLE-008）

### L4 加一个模板 / 改形态池

分清三段，**各自独立、收益不同**：

| 段 | 文件 | 影响 |
|---|---|---|
| ③ 实现 | `templates/scenes/*.html` | 仅 P-forge |
| ② 语义选型 | `domain/scene-semantics.ts` `TEMPLATE_CUES` | 三路径的"旁白语义→模板"映射 |
| ① 候选池 | `recipes/*.json` 的 `templates` 数组（经 `applyStyleVisualPool` 过滤） | 三路径可选范围 |

### L5 加一条审计判据

1. `domain/motion-grammar.ts` `auditMotionMix`（或 `accent-budget.ts`）
2. `docs/10` §5.3 登记 `V-MOT-0xx` + 判据出处（**必须有实测依据，不写口味**）
3. 阈值要能说出"为什么是这个数"（例：amp 0.3 实测=静止，所以 `motifLoop` amp 必须 ≥0.6）

## 六、口径提醒（易错的三个数）

| 说法 | 正确口径 |
|---|---|
| "模板数" | `templates/scenes` 的 HTML 文件数 ≠ `TEMPLATE_CUES` 条数 ≠ `recipes` 里池子数。**三个不同的数**，报数时必须说清是哪个 |
| "语法数" | = `GRAMMARS.length`（跑 `capability` 拿，别数表格行） |
| "原语数" | = `MOTION_WHITELIST.length`（含装配型 `use`/`timeline`，它们不算主动作） |

---

## 七、一句话结论

**吸收外部项目时，先按第三节定位到层，再看第一节确认那条路径是否受该层约束，
最后照第五节清单改完跑 `npm test`。**
最贵错的两次判断是：把 L4 的"模板文件"当成高收益（只救兜底），
以及把 L2 的"语法骨架"当成对主力路径有效（只约束 LLM 路径）。

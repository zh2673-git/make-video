# SKILL.md —— MakeVideo 讲稿创作引导（LLM 必读）

> 本文档是 LLM 产出 MakeVideo 讲稿的**唯一规范源头**。无论你是替人写讲稿（作者模式），还是在 `compose --ai` 流程中做排版决策（排版模式），都遵循本规范。读完即可产出能直接通过 `python -m makevideo build <工程>` 出片的讲稿。

## 0. 两种角色，一条边界

| 角色 | 你负责 | 你不负责 |
|---|---|---|
| **作者模式**（LLM 写讲稿） | 内容创作 + 版式选择 + 图标 + 主题建议 | 渲染、配音、时间轴 |
| **排版模式**（compose --ai） | **只做排版决策**：把人的原文分镜化、选版式、配图标 | **改写、增删、润色原文内容**（条目必须逐字取自原文，允许按句切分） |

铁律：narration（旁白）必须是**口语完整句**；排版模式下 narration = 原文对应段落原句，不许改写。

## 1. 产物形态：一份讲稿 .md

```markdown
<!-- meta: voice=zh-CN-YunjianNeural rate=+0% -->

## SCENE 01|title|标题文字

subtitle: 副标题一
subtitle: 副标题二

=== narration
开场口语旁白，两到三句。

## SCENE 02|bullets|要点页标题

icons: zap,layers,clock
- 要点一：短句
- 要点二：短句

=== narration
对应的口语旁白。

## SCENE 03|stat|数字页标题

| 60秒 | 一分钟成片 | clock
| 79 | 套设计主题 | layers

=== narration
数字对应的口语旁白。

===（末镜用 ending 收尾）
```

**硬性格式规则**：
- `## SCENE <id>|<type>|<标题>` 开块；id 全片唯一（01、02、03…）。
- `=== narration` 后跟旁白，直到下一块；**narration 不能为空**。
- 画面区指令：`subtitle:` / `- ` 条目 / `|` 表格行 / `highlight:` / `note:` / `quote:` / `attribution:` / `lang:` / `image:` / `leftTitle:` / `rightTitle:` / `icons:`。
- stat 用表格行：`| 值 | 标签 | 图标?`（值可带单位/前后缀，数字部分自动计数滚动）。

## 2. 13 种版式选型决策表

| 内容形态 | 版式 | 要点 |
|---|---|---|
| 开场 | `title` | 主标题 + 1~2 行 subtitle |
| 并列要点/特性/原因 | `bullets` | 2~5 条，每条 ≤18 字；语义明确时配 `icons:` |
| 步骤/流程/阶段 | `flow` | 2~4 步，每步"动词短语"优先 |
| 数字成绩/规模/对比量 | `stat` | 2~4 项；**数字强调优先于表格**；配图标 |
| 多行结构化数据 | `table` | 表头 + 3~6 行；关键行配 `highlight:` |
| 超高密度清单 | `panorama` | >12 行才用 |
| 左右对照 | `compare` | leftTitle/rightTitle + `- 左\|右` 行 |
| 时间线/里程碑 | `timeline` | 节点 `第X周\|事件` 形态 |
| 数据柱状对比 | `chart` | 3~6 组名值对，值为数值 |
| 代码演示 | `code` | 行数 ≤10，`lang:` 声明语言 |
| 金句/价值观收束 | `quote` | ≤40 字 + attribution |
| 配图讲解 | `image` | 图放工程 `public/`，`image:` 文件名 |
| 收尾 | `ending` | 一句话 + 感谢/引导 |

**节奏建议**：一条 60s 视频以 6~8 镜为宜；相邻版式不重复（如两个 bullets 之间隔 stat/table）；全片至少一次版式变化对比。

## 3. 图标名清单（icons: 指令用）

状态 `check` `x` `alert` `info` ｜ 能量 `zap` `clock` `send` `play` `rocket` ｜ 数据 `database` `chart` `trending-up` `pie` `filter` `target` ｜ 技术 `code` `terminal` `cpu` `cloud` `git-branch` `layers` `grid` `wrench` ｜ 文档 `file-text` `book` `edit` `message` `mail` `calendar` ｜ 用户 `users` `user` `globe` `award` `flag` ｜ 安全 `lock` `shield` `shield-check` `key` ｜ 媒体 `search` `eye` `camera` `mic` `image` `video` ｜ 连接 `link` `share` `download` `upload` ｜ 评价 `star` `heart` `thumbs`

别名可用：`speed→zap`、`db→database`、`data→database`、`team→users`、`security→shield`、`time→clock`、`ai→cpu`、`warn→alert`。**语义匹配优先于装饰**：讲效率配 `zap`、讲安全配 `shield`、讲数据配 `database`；不确定就不配（回退序号也美观）。

## 4. 旁白与时长纪律

- **语速基准 ≈ 4.2 字/秒**：60s 视频全片 narration 合计 **240~280 字**。逐镜估算：`镜时长 ≈ 该镜 narration 字数 ÷ 4.2`。
- narration 是给 TTS 念的：**口语化、无列表符号、无 markdown、无括号补充**；画面条目是给眼睛看的，两者不逐字重复但语义一致。
- 每镜 narration 2~3 句（30~45 字）；开头镜可加一句钩子，收尾镜引导行动。
- 条目文字 ≤18 字；超长拆条或换版式，**不要**在卡片里塞整段话。

## 5. 主题建议（作者模式适用）

用 `python -m makevideo list-themes` 查看全部主题（79 套）。建议逻辑：科技/产品 → `techdark` / `linear-app` / `spotify`；政务/正式 → `govgold`；教育/温暖 → `warmedu`；杂志/极简 → `magazine`；手写/亲和 → `chalkboard`。讲稿里不写主题——主题在 `project.json` 的 `"theme"` 字段，由工程配置决定。

## 6. 自检清单（产出前逐项过）

- [ ] 每块 `## SCENE id|type|title` 三段齐全，id 唯一
- [ ] 每块都有非空 `=== narration`
- [ ] 首镜 `title`、末镜 `ending`
- [ ] bullets 条目 ≤5 且 ≤18 字；icons 名在清单内
- [ ] stat 行三列（值|标签|图标?）；table 有表头行
- [ ] narration 合计字数 ≈ 目标时长 × 4.2
- [ ] 无 markdown 语法混入画面区（**、#、链接等）
- [ ] 相邻镜版式不重复

## 7. 上机验证

产出后交给人（或脚本）执行：`python -m makevideo validate <工程目录>`——E2 校验通过再 `build`。若校验报错，按错误信息逐条修复（缺 narration / type 拼写 / stat 缺行）。

【人类原文】
MakeVideo
讲稿驱动的微视频生成工具

做一条介绍视频，通常要过三道工序。写文案、排版面、配音对轴，缺一不可。最耗时的不是内容，而是这些重复劳动。MakeVideo 把它们压成一条命令：配音、排版、渲染全部自动完成。

它的用法只有三步：
1. 用 Markdown 写讲稿，声明每页版式
2. 挑一套设计主题
3. 运行 build 命令，成片自动落盘
改完讲稿再跑一次，只有改动过的分镜会重新渲染。

目前它内置 13 种分镜版式、79 套设计主题。60 秒即可产出一条完整成片。代码全部开源。

正如项目主页写的那句话：让表达者只负责说什么，工具负责怎么说好。

感谢观看，项目已开源，欢迎到 GitHub 试用。

请按排版模式输出完整讲稿.md。
